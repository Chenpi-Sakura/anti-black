# 新黑产类别自动发现规划

**版本**：V1.0
**日期**：2026-05-27
**状态**：规划中

---

## 1. 背景与问题

### 1.1 现状

当前分类体系是**静态预置**的，4 个一级分类、若干二级分类硬编码在 `pipeline/classifier.py` 中：

```python
# 账号交易
{'账号交易', ['账号交易', '账号买卖', '出号', '换绑', '租号', '账号转让']}
# 诈骗引流
{'诈骗引流', ['诈骗', '引流', '刷单', '杀猪盘', '兼职诈骗']}
# 流量作弊
{'流量作弊', ['刷粉', '刷赞', '刷量', '流量作弊', '涨粉']}
# 黑产工具
{'黑产工具', ['接码', '群控', '黑产工具', '脚本']}
```

**问题**：黑产手法不断进化，出现新类型（如"内部代下"、"薅羊毛"、"跑分洗钱"）时，系统无法自动发现和适应。

### 1.2 目标

当新型黑产套路出现时，系统能够：
1. **自动发现**：从高风险但分类置信度低的文本中检测到异常模式
2. **LLM 验证**：判断是否为新类别，并生成标准化的类别名称和特征词
3. **自动入库**：将新类别合并到分类体系和黑话词典，同步更新历史数据标签

## 2. 设计方案

### 2.1 整体工作流

```
┌─────────────────────────────────────────────────────────────────┐
│                    Category Discovery Pipeline                    │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│  ┌──────────────┐    ┌──────────────┐    ┌──────────────┐       │
│  │  信号检测   │───→│  聚类分析    │───→│  LLM 验证    │       │
│  │  (Signals) │    │  (Clustering)│    │  (LLM Judge) │       │
│  └──────────────┘    └──────────────┘    └──────────────┘       │
│         │                                        │                │
│         │              ┌──────────────┐          │                │
│         └─────────────→│  自动入库   │←─────────┘                │
│                        │  (Auto-enroll)│                          │
│                        └──────────────┘                          │

│                        │ 历史回填   │                              │
│                        └───────────┘                              │
└─────────────────────────────────────────────────────────────────┘
```

### 2.2 Step 1：信号检测

**触发条件**（满足任一）：

| 信号 | 阈值 | 说明 |
|------|------|------|
| 低置信文本累积 | 某类置信度 < 0.6 的文本超过 N 条 | 现有分类器不确定 |
| 新型 slang 爆发 | slang_candidates 出现 > 20 次/天的新词 | 词汇量突增 |
| 聚类离群点 | embedding 空间中出现新的紧密聚类 | 结构变化 |

**数据来源**：
- `clues` 表：`confidence < 0.6` 的记录
- `slang_candidates` 表：新候选词词频统计
- Embedding 聚类中间结果

### 2.3 Step 2：聚类分析

**方法**：对低置信文本做 embedding 向量化，然后用 DBSCAN 或 HDBSCAN 聚类。

```python
from sklearn.cluster import HDBSCAN

def detect_anomaly_clusters(texts: List[str], min_cluster_size: int = 10):
    embeddings = embedding_model.encode(texts)
    clusterer = HDBSCAN(min_cluster_size=min_cluster_size, min_samples=5)
    labels = clusterer.fit_predict(embeddings)

    # 提取离群点（label = -1）组成的异常簇
    anomaly_mask = labels == -1
    if anomaly_mask.sum() < min_cluster_size:
        return []  # 异常点太少，不是有效信号

    # 对正常聚类结果找"新"簇（与现有类别 embedding 均值距离远）
    normal_labels = labels[labels != -1]
    # ... 与现有类别做距离比较
```

**关键判断**：新发现的簇是否与现有 4 个分类都有明显距离（表示可能是新类别）。

### 2.4 Step 3：LLM 验证

对检测到的候选新类别，调用 LLM 进行判断：

**Prompt**：
```
你是一个黑产情报分类专家。以下是从情报数据中发现的异常文本簇：

文本样例：
{cluster_samples}

请判断：
1. 这是一个独立的新黑产类别，还是现有类别的变种？
2. 如果是新类别，给出一个简洁的标准名称（如"薅羊毛"、"跑分洗钱"）
3. 给出 5-10 个该类别的特征关键词/黑话
4. 给出判断理由

请按以下 JSON 格式输出：
{
  "is_new_category": true/false,
  "category_name": "新类别名称"（如果是新类别）,
  "keywords": ["关键词1", "关键词2", ...],
  "confidence": 0.0-1.0,
  "reasoning": "判断理由"
}
```

### 2.5 Step 4：自动入库

**入录条件**：`is_new_category=true` 且 `confidence >= 0.8`

**入库操作**：

1. **更新 slang_mappings 表**（已有机制）：
   ```python
   db.upsert_slang_mapping(
       slang_raw=keyword,
       meaning=keyword,
       regex_pattern=generate_regex(keyword),
       source='auto_discovered',
       verified=True
   )
   ```

2. **更新分类规则**（写一个新函数 `update_taxonomy`）：
   ```python
   def update_taxonomy(new_category: str, keywords: List[str]):
       """动态更新分类关键词到 classifier.py 的规则"""
       # 读取 classifier.py，插入新类别关键词，重写文件
       # 或者：改为从 DB 读取规则（更优雅）
   ```

3. **历史数据回填**：
   ```python
   # 对过去 30 天包含新类别关键词的线索重新分类
   db.update_clues_with_new_category(
       category_name=new_category,
       keywords=keywords,
       days_back=30
   )
   ```

### 2.6 回退机制

万一 LLM 误判，自动加入了一个错误类别怎么办？

- 新类别加入后，设置**观察期**（7 天）
- 观察期内如果新类别文本中"有效高风险情报"占比 < 5%，自动撤销
- 撤销操作：删除 slang_mappings、恢复规则、回填历史数据

## 3. 数据库设计

### 3.1 新增表

#### `category_proposals`（候选类别表）

```sql
CREATE TABLE IF NOT EXISTS antiblack.category_proposals (
    proposal_id VARCHAR(255) PRIMARY KEY,
    cluster_texts JSONB DEFAULT '[]',     -- 聚类文本样例
    cluster_keywords JSONB DEFAULT '[]',  -- 聚类发现的关键词
    llm_judgment JSONB,                    -- LLM 验证结果
    status VARCHAR(50) DEFAULT 'pending', -- pending/confirmed/rejected
    confidence REAL,
    auto_enrolled BOOLEAN DEFAULT FALSE,
    created_at TIMESTAMP DEFAULT NOW(),
    confirmed_at TIMESTAMP,
    rejected_at TIMESTAMP
);
```

#### `taxonomy`（动态分类体系表）

```sql
CREATE TABLE IF NOT EXISTS antiblack.taxonomy (
    level1_id VARCHAR(50) PRIMARY KEY,
    level1_name VARCHAR(100) NOT NULL,
    level2_id VARCHAR(50),
    level2_name VARCHAR(100),
    keywords JSONB DEFAULT '[]',
    source VARCHAR(50) DEFAULT 'preset', -- preset/auto_discovered
    created_at TIMESTAMP DEFAULT NOW(),
    updated_at TIMESTAMP DEFAULT NOW()
);
```

## 7. 风险与注意事项

| 风险 | 缓解措施 |
|------|---------|
| LLM 误判导致错误分类入库 | 置信度阈值 >= 0.8 + 7 天观察期 |
| 聚类效果不稳定（中文短文本） | 配合 slang 信号，不单独依赖聚类 |
| 历史数据回填耗时 | 分批处理，每次最多回填 1000 条 |
| 新类别与现有类别重叠 | LLM 判断时会问"是变种还是新类别"，重合时更新现有类别 |

---

## 8. 验证方式

1. 模拟一批"薅羊毛"类型的低置信文本，观察是否能检测到信号
2. 检查聚类结果是否形成独立簇
3. LLM 判断输出是否为"新类别"
4. 自动入库后，查询 taxonomy 表确认新类别已加入
5. 检查历史数据是否被正确回填标签

## 9. 与黑话学习的关系

新类别发现和黑话学习是**独立的闭环**，但可以协同：

```
新类别发现  ─────────→  新类别关键词  ─────────→  slang_mappings
                                    ↓
                           触发 slang 验证流程
                                    ↓
                            CONFIRMED slang  →  AC自动机
```

**区别**：

| | 新类别发现 | 黑话学习 |
|---|---|---|
| **粒度** | 新风险类别（一级/二级） | 单个黑话词 |
| **输入** | 聚类离群点 + LLM 判断 | 词频统计 + LLM 验证 |
| **输出** | taxonomy 表更新 | slang_mappings 表更新 |
| **自动化** | 全自动（>= 0.8 置信度） | 半自动（CONFIRMED 才入库） |
