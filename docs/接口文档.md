## 1. 文档说明

本文档定义黑灰产情报分析Agent系统对前端页面、飞书Bot适配层和其他业务调用方开放的 RESTful 接口规范。文档聚焦 Demo 阶段可落地的核心能力，覆盖：

- 自然语言查询发起
- 查询任务状态轮询
- 线索列表检索
- 线索详情查看
- 实体画像查看
- 人工反馈纠错
- 分类体系获取
- 报告导出
- 系统概览监控

## 2. 接口通用规则

### 2.1 基础地址

- 生产建议：`https://{domain}/api/v1`
- Demo 默认：`http://127.0.0.1:8000/api/v1`

以下接口 URL 均以 `/api/v1` 为前缀。

### 2.2 请求头格式

所有非文件下载接口统一使用以下请求头：

```http
Content-Type: application/json; charset=UTF-8
Accept: application/json
Authorization: Bearer <access_token>
X-Request-Id: 2f6c6b44f9df4d39b4d6b1b6df2f1001
```

### 2.3 鉴权机制

- 鉴权方式：`Bearer Token`
- 传递位置：请求头 `Authorization`
- 格式要求：`Authorization: Bearer <access_token>`
- Demo 阶段说明：可使用服务端配置的静态 Token；正式环境建议替换为统一身份认证网关签发 Token

### 2.4 参数编码方式

- Path 参数：URL 路径参数，采用 UTF-8 编码
- Query 参数：使用 `application/x-www-form-urlencoded` 风格拼接在 URL 上
- Body 参数：统一为 JSON 对象，字段名使用 `snake_case`

### 2.5 字符编码标准

- 请求编码：`UTF-8`
- 响应编码：`UTF-8`
- 时间格式：统一使用 ISO 8601，例如 `2026-05-23T14:30:00+08:00`

### 2.6 通用响应结构

除下载类接口外，所有接口统一返回以下包裹结构：

```json
{
  "code": 0,
  "message": "ok",
  "request_id": "2f6c6b44f9df4d39b4d6b1b6df2f1001",
  "data": {}
}
```

字段说明：

| 参数名 | 类型 | 说明 | 示例值 |
|--------|------|------|--------|
| code | integer | 业务返回码，`0` 表示成功 | 0 |
| message | string | 返回说明 | ok |
| request_id | string | 请求唯一标识，用于日志排查 | 2f6c6b44f9df4d39b4d6b1b6df2f1001 |
| data | object/null | 业务数据载荷 | `{}` |

### 2.7 HTTP 状态码约定

| HTTP 状态码 | 说明 |
|------------|------|
| 200 | 请求成功 |
| 201 | 资源创建成功 |
| 400 | 请求参数错误 |
| 401 | 未认证或认证失效 |
| 403 | 无权限访问 |
| 404 | 资源不存在 |
| 409 | 资源状态冲突 |
| 429 | 请求过于频繁 |
| 500 | 服务内部错误 |
| 503 | 下游依赖不可用 |

### 2.8 命名兼容约定

- 对外接口主命名统一使用 `query_id` 表示查询任务主键。
- 为兼容需求设计文档中的 `Task ID` 表述，系统可在兼容模式下额外返回 `task_id` 作为别名字段，其值与 `query_id` 完全一致。
- 默认情况下建议只消费 `query_id`；`task_id` 仅用于兼容旧前端、外部系统适配层或历史脚本，不建议新代码继续依赖。
- 新开发代码、数据库字段和前端状态管理建议统一使用 `query_id`，避免同义字段长期并存。

## 4. 接口详细说明

### 4.1 发起自然语言查询

- 接口名称：发起自然语言查询
- 请求方式：`POST`
- 请求 URL：`/api/v1/queries`
- 功能描述：接收自然语言查询，解析查询意图，优先检索本地已有线索；当 `realtime_fetch=true` 或本地结果不足时，异步触发定向采集任务。

#### 请求参数

| 参数名 | 类型 | 是否必填 | 参数位置 | 参数说明 | 示例值 |
|--------|------|----------|----------|----------|--------|
| query_text | string | 是 | Body | 用户自然语言查询文本 | 查询近三天抖音账号买卖的线索 |
| realtime_fetch | boolean | 否 | Body | 是否触发实时抓取，默认 `false` | true |
| channels | array[string] | 否 | Body | 指定采集渠道，不传表示全渠道 | `["telegram","forum"]` |
| time_range | object | 否 | Body | 显式时间范围；不传则从 `query_text` 解析 | `{ "start_time": "2026-05-20T00:00:00+08:00", "end_time": "2026-05-23T23:59:59+08:00" }` |
| risk_types | array[string] | 否 | Body | 指定一级风险类型过滤 | `["账号交易"]` |
| platforms | array[string] | 否 | Body | 指定目标平台 | `["抖音"]` |
| constraints | object | 否 | Body | 其他过滤条件 | `{ "contains_entity_types": ["WECHAT"], "keywords": ["抖号","换绑"] }` |
| page_size | integer | 否 | Body | 首屏返回线索条数，默认 `10`，最大 `50` | 10 |

#### `time_range` 子参数

| 参数名 | 类型 | 是否必填 | 参数说明 | 示例值 |
|--------|------|----------|----------|--------|
| start_time | string | 否 | 开始时间，ISO 8601 | 2026-05-20T00:00:00+08:00 |
| end_time | string | 否 | 结束时间，ISO 8601 | 2026-05-23T23:59:59+08:00 |

#### `constraints` 子参数

| 参数名 | 类型 | 是否必填 | 参数说明 | 示例值 |
|--------|------|----------|----------|--------|
| contains_entity_types | array[string] | 否 | 要求线索中至少包含的实体类型 | `["WECHAT","URL"]` |
| keywords | array[string] | 否 | 额外业务关键词 | `["接码","代实名"]` |
| min_confidence | number | 否 | 最低分类置信度，范围 `0~1` | 0.7 |

#### 响应参数

| 参数名 | 类型 | 说明 | 示例值 |
|--------|------|------|--------|
| query_id | string | 查询任务 ID | qry_20260523_0001 |
| task_id | string/null | 查询任务兼容别名，仅兼容模式返回，值与 `query_id` 相同 | qry_20260523_0001 |
| status | string | 任务状态：`PENDING/RUNNING/PARTIAL_SUCCESS/COMPLETED/FAILED/TIMEOUT` | RUNNING |
| parsed_intent | object | 解析后的查询意图 | `{...}` |
| execution_plan | object | 执行计划摘要 | `{...}` |
| summary | object | 当前查询摘要信息 | `{...}` |
| clue_preview | array[object] | 首屏线索预览列表 | `[{...}]` |

#### `parsed_intent` 字段说明

| 参数名 | 类型 | 说明 | 示例值 |
|--------|------|------|--------|
| time_range | object | 解析出的时间范围 | `{ "start_time": "...", "end_time": "..." }` |
| risk_types | array[string] | 解析出的风险类型 | `["账号交易"]` |
| platforms | array[string] | 解析出的平台 | `["抖音"]` |
| keywords | array[string] | 解析出的关键词 | `["抖号","换绑"]` |

#### `execution_plan` 字段说明

| 参数名 | 类型 | 说明 | 示例值 |
|--------|------|------|--------|
| fetch_mode | string | 执行模式：`local_only/local_plus_realtime` | local_plus_realtime |
| target_channels | array[string] | 实际采集渠道 | `["telegram","forum"]` |
| estimated_cost_level | string | 预估资源消耗等级：`low/medium/high` | medium |
| estimated_finish_seconds | integer | 预计完成耗时，单位秒 | 120 |

#### `summary` 字段说明

| 参数名 | 类型 | 说明 | 示例值 |
|--------|------|------|--------|
| total_clues | integer | 当前已返回的线索总数 | 8 |
| high_risk_clues | integer | 高风险线索数 | 5 |
| processing_progress | integer | 处理进度百分比 | 35 |
| source_hit_count | integer | 已命中的情报源数量 | 2 |

#### 业务异常码

| 异常码 | 说明 |
|--------|------|
| 1001 | `query_text` 为空或长度超限 |
| 1002 | 时间范围不合法 |
| 1003 | 渠道参数不支持 |
| 1004 | 查询任务创建失败 |
| 1005 | 当前任务并发数超过阈值 |

#### 请求示例

```bash
curl -X POST "http://127.0.0.1:8000/api/v1/queries" \
  -H "Content-Type: application/json; charset=UTF-8" \
  -H "Accept: application/json" \
  -H "Authorization: Bearer demo-token" \
  -d '{
    "query_text": "查询近三天抖音账号买卖的线索，优先看带微信号的",
    "realtime_fetch": true,
    "channels": ["telegram", "forum"],
    "platforms": ["抖音"],
    "constraints": {
      "contains_entity_types": ["WECHAT"],
      "min_confidence": 0.7
    },
    "page_size": 10
  }'
```

### 4.4 获取系统就绪状态

- 接口名称：获取系统就绪状态
- 请求方式：`GET`
- 请求 URL：`/api/v1/system/ready`
- 功能描述：返回系统是否已完成冷启动、历史回填和核心依赖检查，供前端判断是否允许用户发起正式查询。

#### 请求参数

无

#### 响应参数

| 参数名 | 类型 | 说明 | 示例值 |
|--------|------|------|--------|
| ready | boolean | 系统是否就绪 | true |
| status | string | 就绪状态：`BOOTSTRAPPING/READY/DEGRADED`，含义：BOOTSTRAPPING=冷启动中，READY=已就绪，DEGRADED=降级运行（部分依赖异常） | READY |
| health_checks | object | 关键依赖健康状态 | `{...}` |
| bootstrap_progress | integer | 冷启动进度百分比 | 100 |
| backfill_entity_count | integer | 历史回填已入库实体数 | 12680 |
| ready_threshold | integer | 就绪阈值 | 10000 |
| updated_at | string | 最近状态更新时间 | 2026-05-23T15:20:00+08:00 |

#### `health_checks` 字段说明

| 参数名 | 类型 | 说明 | 示例值 |
|--------|------|------|--------|

### 5.4 接口调用注意事项

1. 查询类接口建议前端设置 30 秒超时，超时后通过任务状态接口继续轮询。
2. `POST /queries` 创建任务后，不保证首帧结果完整；前端应以 `query_id` 为主键继续轮询。
3. Demo 阶段导出接口建议限制单次导出数据量，默认不超过 5000 条。
4. `relation_depth` 最大值建议为 `2`，避免图谱查询耗时过长。
5. 所有调用方都应透传 `X-Request-Id`，便于问题排查。
6. 错误响应中 `message` 仅用于提示，前端逻辑判断应以 `code` 为准。

### 5.5 内部实现说明

下列能力属于系统内部处理逻辑，不单独通过对外 RESTful 接口暴露，但会通过业务结果或监控字段间接体现：

1. 图片下载失败重试、OCR 提取、VLM 降级调用等图片处理细节。
2. LLM 主备切换、超时降级、Token 配额控制等下游依赖治理逻辑。
3. 增量采集的 `last_seen` 判断、去重缓存、消息级失败丢弃等流水线内部策略。
4. 图谱构建通道的具体工作池调度、Prompt 细节、LightRAG 内部插入流程。

### 5.6 模型更新状态机说明

`model_update_status`（`POST /feedback` 响应）和 `retrain_status`（`GET /evolution/status` 响应）共用同一状态机，用于描述自进化模块的模型更新进度：

| 状态 | 说明 | 后续状态 |
|------|------|----------|
| IDLE | 空闲，当前无训练任务 | ← DEPLOYED；→ QUEUED（样本量达阈值时） |
| QUEUED | 训练任务已入队，等待调度 | → TRAINING |
| TRAINING | 模型正在训练中 | → EVALUATING |
| EVALUATING | 新模型评估中（Macro F1 提升 >2% 且各类别 Recall 未断崖） | → DEPLOYED / FAILED |
| DEPLOYED | 新模型已上线替换 | → IDLE |
| FAILED | 训练或评估未通过，自动回退至上一版本 | → IDLE |

**状态流转图**：
```
IDLE ←→ QUEUED → TRAINING → EVALUATING → DEPLOYED
                     ↓            ↓
                   FAILED ←───────┘
```

**轮询建议**：
- `POST /feedback` 返回 `model_update_status=QUEUED` 时，前端可等待 5 秒后调用 `GET /evolution/status` 查询 `retrain_status` 是否进入 TRAINING 阶段。
- 模型更新为后台异步任务，不阻塞前端其他操作。
