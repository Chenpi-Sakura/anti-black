# Trace Actor Skill

## 何时使用
用户输入形如"分析这个微信号xxx"、"这个人的活动轨迹"、"帮我溯源xxx号"。通过关键词命中 / 追查实体活跃历史等意图触发。

## 强制工作流（按顺序执行）
1. **第一步必须调 `get_actor_footprint`**（`entity_value` 必填，`entity_type` 可选）
   - 拿到时间线 + 风险历史 + 实体元数据
   - 如果返回"未找到实体"，报告说明后停止，**不要继续**调 kg_query
2. **第二步调 `kg_query`**（`mode=mix`, `limit=15`）
   - 挖掘该实体的上下游关联节点
3. **第三步按需调 `search_clues` / `get_clue_detail`**
   - 对 1-2 条关键线索钻取细节
   - 不要超过 2 次额外调用
4. **生成报告**

## 无追问规则（继承 CORE）
- 不允许要求用户提供更多信息（"请提供微信号"、"你没给实体值"等均禁止）
- 实体不明确时（如"帮我分析一下"），假设是从 search_clues 中找到的实体，用搜索结果推
- 实体未找到 → 报告说明"未找到该实体活跃记录"，继续走 kg_query 看是否有关联网络

## 输出结构（强制 Markdown 排版）
一、**实体画像表**：标识 | 类型 | 首次出现 | 活跃平台数
二、**跨平台活动时间线**：按日期降序，10-20 条
三、**上下游关联网络**（树状图 ├─→ / └─→）
四、**风险历史与近期可疑线索**
五、**综合研判**

## 错误兜底
- 实体未找到 → 报告说明"未发现该实体活跃记录"
- kg_query 返回空 → 报告说明"未发现关联网络"
- 时间线为空 → 报告说明"暂无跨平台活跃记录"
